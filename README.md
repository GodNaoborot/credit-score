# Credit risk - скоринг по анкете клиента

WOE-скоркарта на Home Credit Default Risk. Сервис принимает анкету, возвращает
вероятность дефолта, решение и причины отказа.

## Задача

Для нового клиента, о котором известны только заполненные им поля:

1. оценить вероятность дефолта;
2. принять решение одобрить или отказать;
3. при отказе указать, какие признаки его вызвали.

`EXT_SOURCE_1/2/3` (готовые баллы внешних бюро) из набора исключены: клиент их
не вводит, и в причине отказа непрозрачный балл предъявить нельзя.

## Данные

`application_train.csv`, 307 511 заявок, 122 колонки, плюс три агрегата
кредитной истории из `bureau.csv`.
`TARGET = 1` - просрочка сверх N дней на одном из первых платежей, доля 8.07%.

Датасет: [Home Credit Default Risk](https://www.kaggle.com/c/home-credit-default-risk).
В репозиторий не входит - 2.5 ГБ, семь файлов свыше лимита GitHub в 100 МБ.

```bash
kaggle competitions download -c home-credit-default-risk -p datasets/
unzip datasets/home-credit-default-risk.zip -d datasets/
```

Обученная скоркарта лежит в `artifacts/scorecard.json` (9 КБ) - сервис
поднимается без датасета, он нужен только для `scripts/train.py`.

## Отбор признаков

Три фильтра последовательно, 117 → 14, плюс три признака кредитной истории.

**1. IV > 0.02.** Осталось 49.

```
IV = Σ (доля_хороших_i − доля_плохих_i) · WOE_i
```

**2. Продуктовый критерий.** Осталось 14. Удалены:

| блок | признаков | причина |
|---|---|---|
| характеристики дома | 27 | данные внешнего реестра, клиент не вводит |
| внутренние данные банка | 6 | рейтинг региона, даты смены документов и телефона |
| выводимые из адреса | 3 | несовпадения адресов, населённость региона |
| дубль рейтинга региона | 1 | `r = 0.95` со вторым |

**3. Проверка знаков коэффициентов.** На WOE все коэффициенты обязаны быть
отрицательными. Выбившийся означает дубль или перевёрнутое направление.

- `FLAG_EMP_PHONE` удалён: совпадает с сентинелом стажа на 99.996%,
  корреляционная матрица дубль не показала.
- `AMT_CREDIT` оставлен (`r = 0.987` с `AMT_GOODS_PRICE`). Знак выправлен
  заданием направления монотонности, см. ниже.

В финальной модели признаков с неправильным знаком нет.

**Возвращён вопреки IV:** `AMT_INCOME_TOTAL` (`IV = 0.011`). Обязателен по
регуляторным требованиям к оценке платёжеспособности и нужен знаменателем для `DTI`.

### Кредитная история

Три агрегата из `bureau.csv`, все три клиент называет по памяти:

| признак | что это |
|---|---|
| `N_ACTIVE_CREDITS` | сколько кредитов открыто сейчас |
| `CURRENT_DEBT` | суммарный остаток долга по ним |
| `FIRST_CREDIT_DAYS` | когда взят первый кредит, дней до заявки |

Различаются два случая: истории нет вовсе (`NaN`, дефолт 7.83%) и история есть,
но активных кредитов нет (долг 0, дефолт **5.78%** - самая безопасная группа).

Вклад блока - `+0.048 Gini`, из них основное даёт давность первого кредита,
а не размер долга:

| набор | ROC-AUC | Gini |
|---|---|---|
| 14 анкетных | 0.6537 | 0.3074 |
| + только `CURRENT_DEBT` | 0.6598 | 0.3195 |
| **+ все три** | **0.6779** | **0.3557** |

Замер сделан на фактических значениях из `bureau.csv`. Заявитель долг занизит,
а давность первого кредита вспомнит приблизительно - в проде блок даст меньше.

Производные, считаются из уже заполненных полей:

```
DTI         = AMT_ANNUITY / AMT_INCOME_TOTAL · 100
TERM_MONTHS = AMT_CREDIT / AMT_ANNUITY
OVERPAY     = (AMT_CREDIT − AMT_GOODS_PRICE) / AMT_GOODS_PRICE
```

## Модель

Логистическая регрессия на WOE-кодировании.

```
WOE_i = ln( доля_хороших_i / доля_плохих_i )        сглаживание (n + 0.5) / (N + k · 0.5)

logit P(дефолт) = b₀ + Σ b_i · WOE_i
```

Границы корзин: 20 квантильных пре-корзин, затем жадное слияние соседних пар,
пока доля дефолтов не пойдёт монотонно в заданном направлении. Корзины меньше
3% выборки сливаются с соседом.

Направление задано в `config.MONOTONIC_DIRECTION`:

| признак | тренд доли дефолтов |
|---|---|
| `AMT_CREDIT`, `AMT_ANNUITY`, `AMT_GOODS_PRICE`, `DTI`, `OVERPAY`, `DAYS_EMPLOYED` | ascending |
| `AMT_INCOME_TOTAL`, `TERM_MONTHS` | descending |

В данных крупные кредиты и платежи имеют более низкий дефолт: LTI 10+ - 6.59%
против 8.77% у LTI 2-4. Такие кредиты выдавались более проверенным клиентам,
поэтому размер займа кодирует глубину проверки, а не платёжеспособность.

Монотонность стоит 0.011 AUC относительно свободного квантильного биннинга
(0.6615 → 0.6537).

Границы корзин и WOE замораживаются на train и переиспользуются на valid.
Сплит 75/25, стратифицированный, выполняется до подсчёта редких категорий.

## Метрики

Оценка на отложенной выборке, 76 878 заявок.

```
ROC-AUC = P(скор случайного дефолтника > скор случайного недефолтника)
Gini    = 2 · ROC-AUC − 1
PR-AUC  = площадь под кривой точность-полнота; базовый уровень = доля дефолтов
Brier   = (1/n) Σ (p_i − y_i)²
```

| метрика | значение |
|---|---|
| ROC-AUC | 0.6779 |
| Gini | 0.3557 |
| PR-AUC | 0.1637 (базовый 0.0807) |
| Brier | 0.07155 |
| доля одобрений | 92.8% |
| дефолт среди одобренных | 7.00% (база 8.07%) |

Калибровка: ECE 0.0038, средний предсказанный PD совпадает с фактическим 0.0807. Взвешивание классов и передискретизация не применяются - логрегрессия
обучается максимумом правдоподобия на том же распределении и калибруется сама.

Изотоническая калибровка поверх доступна по ключу `--calibrate`: сплит становится
трёхсторонним, калибратор учится на отдельной выборке. По замеру не окупается:

| | без калибровки | с калибровкой |
|---|---|---|
| train | 230 633 | 184 506 |
| ECE | 0.00465 | 0.00419 |
| ROC-AUC | 0.6537 | 0.6523 |
| PR-AUC | 0.1506 | 0.1445 |
| Brier | 0.07219 | 0.07225 |

Изотоника ступенчатая: она склеивает разные скоры в равные и теряет разрешение
ранжирования. Выигрыш в ECE 0.0005 при потере 0.006 PR-AUC и 20% обучающей
выборки. По умолчанию выключена.

## Порог одобрения

Одобряем, пока ожидание положительно:

```
(1 − p) · маржа > p · LGD

p* = маржа / (маржа + LGD)
```

Сумма кредита сокращается: и маржа, и LGD пропорциональны экспозиции, поэтому
порог один для всех.

```
маржа = 0.1367    медиана положительной наценки (AMT_CREDIT − AMT_GOODS_PRICE) / AMT_CREDIT
LGD   = 0.70      допущение, в данных отсутствует
p*    = 0.1634
```

`LGD` в датасете нет - ни ставок восстановления, ни данных о взысканиях.
Чувствительность:

| LGD | p* | одобрено | дефолт одобренных |
|---|---|---|---|
| 0.5 | 0.2148 | 98.7% | 7.82% |
| 0.6 | 0.1856 | 96.9% | 7.55% |
| 0.7 | 0.1634 | 94.3% | 7.30% |
| 0.8 | 0.1460 | 91.1% | 6.99% |

Эмпирический максимум прибыли на отложенной выборке - порог 0.150 против 0.163
по формуле. Кривая прибыли около максимума плоская. Расхождение от того, что в
расчёте используется одна медианная маржа, а фактическая наценка у каждой заявки
своя и коррелирует с риском.

## Политика

Жёсткие отсечения до модели. Модель обучена на выданных кредитах и за пределами
этого диапазона не экстраполирует: биннинг клампит крайние значения, заявка на
4 млн при доходе 25 тыс попадает в те же корзины, что обычная.

```
доход < 20 000              платёж ≥ дохода
DTI > 50%                   LTI > 10
срок вне 8-48 месяцев
```

Границы срока взяты по диапазону данных: минимум в выборке 8.0 месяцев,
заявок короче нет.

Ответ различает `refused_by: "policy"` и `"scorecard"`.

## Причины отказа

Балл раскладывается по признакам:

```
Factor = PDO / ln(2) = 20 / ln 2 = 28.85
Offset = 600 − Factor · ln(50) = 487.1

баллы_i = Offset/n − Factor · b₀/n − Factor · b_i · WOE_i
Score   = Σ баллы_i = Offset + Factor · ln(шансы быть хорошим)
```

600 баллов соответствуют шансам 50:1, каждые +20 баллов удваивают отношение.

Причина = сколько баллов потеряно относительно типичного заявителя:

```
потеряно_i = баллы_i(средний WOE по популяции) − баллы_i(факт)
```

База в разности сокращается. Сортировка по убыванию, топ-3 - причины отказа.

`relative_to='max'` считает относительно лучшей корзины признака. По
`TERM_MONTHS` в худшую корзину попадают 59.5% заявителей, поэтому срок при этой
конвенции выпадает в причины большинству.

## Ограничения

- **Selective labels.** В данных только выданные кредиты. Модель валидна на
  области, похожей на одобренных.
- **Out-of-time валидация невозможна** - календарной даты в датасете нет,
  только относительные `DAYS_*`.
- **`OVERPAY` эндогенен.** Наценку назначает банк по своей оценке риска. Требует
  проверки, известна ли она клиенту до подачи заявки.
- **`CODE_GENDER` запрещён** в кредитных решениях (ЕС, ECOA). Отключается
  `DROP_PROHIBITED = True` в `src/config.py`, стоит 0.037 IV.
- **Заявленный доход почти не предсказывает дефолт.** У нижних 70% распределения
  уровень плоский, 8.2-8.9%. Работает только в отношениях.
- **`FLAG_OWN_REALTY` не несёт сигнала** - IV 0.0003, дефолт 8.32% против 7.96%.

## Запуск

```bash
pip install -r requirements.txt

python scripts/train.py            # -> artifacts/scorecard.json
uvicorn app.main:app --reload      # -> localhost:8000
```

Флаги обучения: `--binning quantile`, `--lgd 0.6`, `--out путь`.

### API

```
POST /api/score     анкета -> pd, score, approved, refused_by, violations, reasons
GET  /api/limits    границы политики
GET  /api/health    состояние, порог, Gini
```

## Структура

```
src/
  config.py      признаки, пороги, направления монотонности, LGD, калибровка баллов
  data.py        загрузка, чистка, производные, сплит, редкие категории
  binning.py     биннинг + WOE, спецификация обычным словарём
  scorecard.py   Scorecard: fit, predict_proba, points, reasons, save/load
  policy.py      правила отсечения до модели
scripts/train.py обучение и сохранение артефакта
app/main.py      FastAPI: форма и API
notebooks/       разведка, EDA, обоснование решений
artifacts/       scorecard.json - границы корзин, WOE, коэффициенты, порог
```

`scorecard.json` - 9 КБ: границы корзин, WOE, коэффициенты, калибровка баллов,
порог, метрики. Инференс - поиск по границам и арифметика.
